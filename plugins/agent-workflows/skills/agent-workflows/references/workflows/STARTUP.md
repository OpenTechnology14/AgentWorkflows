# Startup and authority

> **Status:** Maintained reusable procedure · Target-project rules retain authority


- Resolve the actual project, checkout, branch/worktree and owner of existing edits. Read the target's root/subdirectory instructions and applicable skills before editing.
- Use a private project adapter and its local configuration when available to locate the existing guide, canonical queue, coordinator and model rules. A new unrelated checkout does not inherit an installed project's authority.
- If a project has `.agent-workflows.json`, check its accepted revision/hashes and upstream status using the [direct-reference workflow](PROJECT_REFERENCE.md). Read the accepted workflows directly; disclose stale/missing/unavailable evidence. Project rules and short fallback remain usable.
- Current explicit owner instructions govern the requested scope; preserve project-specific product/security rules and recorded holds. Resolve contradictions visibly instead of flattening them into one universal stack or model rule.
- Read the selected item's current proposal, decision history, source, tests and PR. Source snapshots are evidence of an inspected revision, not current production truth.
- Identify your role: facilitator/coordinator, worker or reviewer. Reuse current assignments and separate writing worktrees. Do not create another coordinator or timer merely because a chat is new.
- Register the item before you start it ([entry gate](ENTRY_GATE.md)) and give it one Kind from [work types](WORK_TYPES.md).
- For kickoff, continuation and owner answers, use [How we work together](WORKING_TOGETHER.md): accept short ordinary input, recover existing state and respond with Changed / Needs your answer / Next.
- Generate a bounded current-stage prompt from the owner's insight and available evidence. Continue authorized work; ask only the consequential missing choice. Report unavailable sources or delivery precisely.
- Other-project rules remain adapters: React/Next.js, native desktop, Python, Unreal and local game projects have different build, privacy, model and acceptance requirements.
