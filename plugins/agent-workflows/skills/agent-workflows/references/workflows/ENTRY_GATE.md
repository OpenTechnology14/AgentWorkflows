# Entry gate — register, then start

> **Status:** Maintained reusable procedure · Target-project rules retain authority

Before any agent session starts work, whether from a coordinator's brief, an owner's sentence or its own initiative, the work has a row in the project's work view. Registering is an agent task. It is not owner paperwork and it is not approval.

1. Resolve the project, checkout and your role ([startup](STARTUP.md)).
2. Look for the item: the canonical queue, open pull requests and assignments, and the work, idea and question views. If it exists, attach to it and continue from its current stage. Never open a second row for the same outcome.
3. If it does not exist, write one short row: project, canonical parent or temporary key, [Kind](WORK_TYPES.md) (housekeeping, with the reason, when nothing else fits), state, the owner's words or the source, and the next prompt or "this session's brief".
4. Check holds and authority. Registering an item does not approve it, and a held topic stays held.
5. Then start. Work without a row does not start, except urgent security triage, which is registered as soon as it is safe to.
6. Report the row key in your first update. At the end, update the state, link the pull request or result, and move any open choice to the question list.

**Who writes the row.** The project's facilitator or coordinator persists it. A worker proposes the row in its first message. It writes the row itself only if it can write to the private work view, re-reads the file immediately before saving, preserves other edits and stops on a concurrent change. If it can do neither, it says registration is prepared but not persisted.

**Proportion.** A one-line row and a stated Kind are enough. A task whose brief is already in the session needs no prompt file: record "this session's brief". Later sessions on the same item reuse its row.

**Failure.** If the work view is unreachable, say so, keep the row in the conversation and register when access returns. Read-only investigation does not wait for registration. A row that was never persisted is reported as not persisted, not as tracked.
