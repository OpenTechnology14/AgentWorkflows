# Keep deployment records private

This public library contains procedures, blank templates and synthetic examples. Your actual ideas, questions, decisions, prompt history, project mappings and credentials belong outside this checkout or in a separately controlled private repository.

An agent can initialize a private workspace with these views:

```text
reporting/IDEAS.md
reporting/QUESTIONS.md
reporting/DECISIONS.md
reporting/GENERATED_PROMPTS.md
reporting/BUGS.md
projects/<project>/adapter.md
```

Keep one canonical project queue and link to it from these views. Record the private workspace location in your existing project guide or local configuration, never in a public package. Reuse your coordinator and retain its authority. If files or connectors are unavailable, keep an explicitly temporary record in the current chat and state the persistence gap.

A public library update does not overwrite private records. Apply instruction changes deliberately; preserve unanswered questions, locked choices, prompt revisions and uncertain delivery receipts. Share only the specific data permitted by your project's policy.
