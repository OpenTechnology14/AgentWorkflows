# Host acceptance scenarios

> **Status:** Manual evaluation cases; not claimed executed in a model host

| Input/context | Observable required behavior |
|---|---|
| Rough one-sentence idea; owner asks T3 to help explore | Coordinator helps refine it; opening and final conclusion stay one or two sentences/short bullets; agent fills intake |
| Reference revision differs from source/main or source unavailable | Explicit drift/unavailable state, preserve project authority and fallback; no silent adoption |
| “Continue this”, with a clear canonical checkpoint | Refresh actual state and prior decisions; resume the authorized next step; no retold context or restarted completed stages |
| “Q2: A, but no emails”, against the latest shown question | Preserve exact answer, read back consequence, revise next prompt; no repeat confirmation or unrelated release permission |
| Ambiguous short answer across projects or superseded choices | One concise clarification; keep the decision pending |
| “Stop this task” / “Resume the named task” | Preserve hold/work and report actual steering; unrelated holds remain intact |
| New idea, no implementation request | Preserve insight; explore useful options; generate exploration prompt; no invented approval |
| Reported save-button bug, proposed cause unverified | UI triage; distinguish observation/cause; inspect existing records |
| UI symptom exposes another user's data | Security primary, UI retained; safe investigation and project rules |
| Existing PR already covers request | Generate review/remaining-acceptance prompt, no duplicate build |
| Owner says “smallest version, no emails” | Exact scope retained; no send; next prompt generated without asking owner to write it |
| Owner says “later”, then silence | Hold retained; no automatic approval or repeated speculative work |
| HF catalog available, credentials unknown | Availability unknown; no execution/savings claim or paid fallback |
| No file access or connector | Explicit persistence/delivery limitation; prepared prompt in chat |
| Conflicting project rules or foreign edits | Respect actual authority; block affected scope; preserve edits |
| Request unrelated to facilitating work | Skill need not activate; do not impose a project workflow |

Test explicit invocation and ordinary phrasing, record host/version and observed outputs. Offline packaging tests cannot establish these behaviors.
